title: Async evaluation
description: Run scripts that use await and async host functions, and how quickjs-rs counts time while they wait.
---

Tool calls are usually slow and usually async. `eval_async` runs a script that can `await` at the top level, drives
its promises from asyncio, and returns the value of the last expression.

## The basics

```python
import asyncio

from quickjs_rs import Runtime


async def main() -> None:
    with Runtime() as rt, rt.new_context() as ctx:

        @ctx.function
        async def fetch_user(user_id: int) -> dict:
            return {"id": user_id, "team": "infra"}

        @ctx.function
        async def fetch_team(name: str) -> list[str]:
            return ["Ada", "Grace"]

        print(await ctx.eval_async("""
            const user = await fetch_user(7);
            const members = await fetch_team(user.team);
            members.length
        """))
        #> 2


asyncio.run(main())
```

The result is the value of the last statement, as in a REPL. Top-level `const` and `let` bindings stay defined for
later evals on the same context.

| Method | Returns |
| --- | --- |
| `await ctx.eval_async(code)` | The last value, converted to Python. |
| `await ctx.eval_handle_async(code)` | The last value as a `Handle`. |
| `await ctx.eval_async(code, module=True)` | `None`. The code runs as an ES module. See [modules](/concepts/modules). |
| `await handle.await_promise()` | A `Handle` to what an existing promise settles to. |

Each accepts `timeout=` to override the context's timeout for one call.

## Only JavaScript time counts

The timeout bounds time spent running JavaScript. While a script waits on an async host function, the clock stops.

```python
import asyncio

from quickjs_rs import Runtime


async def main() -> None:
    with Runtime() as rt, rt.new_context(timeout=0.2) as ctx:

        @ctx.function
        async def slow_tool() -> str:
            await asyncio.sleep(0.5)
            return "done"

        print(await ctx.eval_async("await slow_tool()"))
        #> done


asyncio.run(main())
```

The tool took 0.5 seconds, more than the 0.2-second timeout, and the eval still succeeded. This keeps slow tools from
eating a script's budget. It also means a script that keeps awaiting tools can run for as long as the tools keep
answering. To bound the whole run, wrap it in `asyncio.timeout()`:

```python
import asyncio

from quickjs_rs import Runtime


async def main() -> None:
    with Runtime() as rt, rt.new_context() as ctx:

        @ctx.function
        async def slow_tool() -> str:
            await asyncio.sleep(10)
            return "done"

        try:
            async with asyncio.timeout(0.1):
                await ctx.eval_async("await slow_tool()")
        except TimeoutError:
            print("run took too long")
            #> run took too long


asyncio.run(main())
```

Leaving the `asyncio.timeout()` block cancels the eval and its host calls. See
[cancellation](/concepts/host-functions#cancellation).

## Stuck scripts raise instead of hanging

If a script waits on a promise that nothing can ever settle, `eval_async` raises `DeadlockError`:

```python
import asyncio

from quickjs_rs import DeadlockError, Runtime


async def main() -> None:
    with Runtime() as rt, rt.new_context() as ctx:
        try:
            await ctx.eval_async("await new Promise(() => {})")
        except DeadlockError:
            print("deadlock")
            #> deadlock


asyncio.run(main())
```

The usual cause is a promise whose `resolve` is never called. Another is an async function that a decorator made look
sync, so it was registered as sync. Pass `is_async=True` when you register it.

## One async eval at a time

A context runs one `eval_async` at a time. Starting a second while the first is waiting raises `ConcurrentEvalError`.
Contexts are cheap, so use one per concurrent run.

## Sync eval does not run promise callbacks

A sync `eval` runs the script and returns. It does not run `.then` callbacks or code after an `await`. Those run the
next time something drives the context:

```python
import asyncio

from quickjs_rs import Runtime


async def main() -> None:
    with Runtime() as rt, rt.new_context() as ctx:
        print(ctx.eval("Promise.resolve(1).then((v) => (globalThis.got = v)); typeof got"))
        #> undefined
        print(await ctx.eval_async("await null; got"))
        #> 1


asyncio.run(main())
```

A sync `eval` whose result is a promise raises `MarshalError`. Use `eval_async`, or `eval_handle` and then
`await_promise()`.

## Keep scripts off your event loop

`eval_async` runs JavaScript on the thread that awaits it. A script stuck in a loop blocks that event loop until it
awaits a host function or hits its timeout. To keep your application responsive, run scripts on a
[`ThreadWorker`](/concepts/threads).
