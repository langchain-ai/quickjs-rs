title: Host functions
description: Expose Python functions to JavaScript as tools, sync or async, and control what scripts see when they fail.
---

A host function is a Python function that scripts can call. It is the only way a script reaches anything outside the
sandbox, so it is both the main feature and the main risk.

## The basics

`@ctx.function` installs a function as a JavaScript global. The global's name is the function's name.

```python
from quickjs_rs import Runtime

with Runtime() as rt, rt.new_context() as ctx:

    @ctx.function
    def get_temperature(city: str) -> float:
        return {"London": 21.5, "Oslo": 4.0}[city]

    print(ctx.eval("`${get_temperature('London')} degrees`"))
    #> 21.5 degrees
```

To pick a different JavaScript name, pass `name=`. To register a function you did not define with a decorator, use
`ctx.register`:

```python
from quickjs_rs import Runtime

with Runtime() as rt, rt.new_context() as ctx:

    @ctx.function(name="getUser")
    def get_user(user_id: int) -> dict:
        return {"id": user_id, "name": "Ada"}

    ctx.register("upper", str.upper)

    print(ctx.eval("upper(getUser(7).name)"))
    #> ADA
```

Host functions belong to one context. A new context, or a context restored from a snapshot, starts with none.
Registering a name again replaces the old function.

## Arguments and return values

Arguments arrive as Python values, converted by the rules in [values](/concepts/values). Return values convert back
the same way.

```python
from quickjs_rs import Runtime

with Runtime() as rt, rt.new_context() as ctx:

    @ctx.function
    def describe(*args: object) -> str:
        return repr(args)

    print(ctx.eval("describe(1, 'two', [3], { four: 4 }, null)"))
    #> (1, 'two', [3], {'four': 4}, None)
```

JavaScript passes every argument the caller wrote, so match your signature to how scripts call it.
`items.map(fn)` passes three arguments (the value, the index, and the array). Write `items.map((x) => fn(x))`, or give
the function `*args`.

Arguments that cannot be converted, such as a function or a promise, make the call fail before your code runs.
JavaScript's `this` is not passed.

## Errors

When a host function raises, the script receives an `Error` named `HostError` with the message
`Host function failed`. The message is the same for every failure. It never includes the Python exception, its type,
or the function's name, so nothing from your process leaks into the script.

```python
from quickjs_rs import Runtime

with Runtime() as rt, rt.new_context() as ctx:

    @ctx.function
    def charge(amount: int) -> str:
        if amount > 100:
            raise ValueError(f"amount {amount} exceeds the card limit")
        return "ok"

    print(ctx.eval("try { charge(500) } catch (e) { e.message }"))
    #> Host function failed
```

If the script does not catch the error, the eval raises your original exception:

```python
from quickjs_rs import Runtime

with Runtime() as rt, rt.new_context() as ctx:

    @ctx.function
    def charge(amount: int) -> str:
        raise ValueError(f"amount {amount} exceeds the card limit")

    try:
        ctx.eval("charge(500)")
    except ValueError as e:
        print(e)
        #> amount 500 exceeds the card limit
```

To tell the script what went wrong, return a value that says so, such as `{"error": "amount too large"}`.

## Async host functions

An `async def` host function returns a promise. Run scripts that call one with `eval_async`.

```python
import asyncio
import time

from quickjs_rs import Runtime


async def main() -> None:
    with Runtime() as rt, rt.new_context() as ctx:

        @ctx.function
        async def fetch_user(user_id: int) -> dict:
            await asyncio.sleep(0.2)
            return {"id": user_id}

        start = time.perf_counter()
        ids = await ctx.eval_async("""
            const users = await Promise.all([1, 2, 3].map((id) => fetch_user(id)));
            users.map((u) => u.id)
        """)
        print(ids, round(time.perf_counter() - start, 1))
        #> [1, 2, 3] 0.2


asyncio.run(main())
```

Each call runs as an asyncio task, so the three calls above run at the same time. The script takes about 0.2
seconds, not 0.6. When a task finishes, its result
resolves the promise, or its exception rejects it with the same `HostError` as a sync failure.

Async host functions need an event loop to run on. Calling one from a sync `eval` raises `ConcurrentEvalError`.

quickjs-rs detects async functions with `inspect.iscoroutinefunction`. If a decorator hides that, registration raises
`TypeError` rather than guessing. Pass `is_async=True` or `is_async=False` to `register` or `function` to decide.

## Sync host functions block

A sync host function runs on the thread that is evaluating, while the script waits. The timeout cannot interrupt it:
a sync function that blocks for 10 seconds holds the context for 10 seconds. Keep sync functions fast, and make
anything that does I/O `async`.

A sync host function must not call `eval` on its own context.

## Cancellation

If the task running `eval_async` is cancelled, every host call still in flight is rejected with an error named
`HostCancellationError`. The script's `catch` and `finally` blocks then get one chance to run.

```python
import asyncio

from quickjs_rs import Runtime


async def main() -> None:
    with Runtime() as rt, rt.new_context() as ctx:

        @ctx.function
        async def slow_tool() -> str:
            await asyncio.sleep(10)
            return "done"

        task = asyncio.create_task(ctx.eval_async("""
            try { await slow_tool() }
            catch (e) { `cleaned up after ${e.name}` }
        """))
        await asyncio.sleep(0.05)
        task.cancel()
        print(await task)
        #> cleaned up after HostCancellationError


asyncio.run(main())
```

If the script handles the cancellation and returns a value, `eval_async` returns it. Otherwise `eval_async` raises
`asyncio.CancelledError`.

## Budget your tools

quickjs-rs does not limit how many host calls a script makes, or how many run at once. A script can start 100,000 async
calls with one `Promise.all`. Put the limit inside the tool:

```python
import asyncio

from quickjs_rs import Runtime


async def main() -> None:
    gate = asyncio.Semaphore(4)
    calls = 0

    with Runtime() as rt, rt.new_context() as ctx:

        @ctx.function
        async def search(query: str) -> str:
            nonlocal calls
            calls += 1
            if calls > 10:
                raise RuntimeError("search budget exhausted")
            async with gate:
                await asyncio.sleep(0.01)
                return query.upper()

        print(await ctx.eval_async("""
            const results = await Promise.allSettled(
                Array.from({ length: 12 }, (_, i) => search(`q${i}`))
            );
            results.filter((r) => r.status === "fulfilled").length
        """))
        #> 10


asyncio.run(main())
```
