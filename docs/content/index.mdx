quickjs-rs runs JavaScript and TypeScript from Python inside a WebAssembly sandbox. The JavaScript engine is
[quickjs-ng](https://quickjs-ng.github.io/quickjs/), reached through the [rquickjs](https://github.com/DelSkayn/rquickjs)
bindings and compiled to `wasm32-wasip1`. [wasmtime](https://wasmtime.dev/) runs that module inside your Python
process. The package is pure Python: one universal wheel that carries the compiled `.wasm` files, with `wasmtime` as
its only runtime dependency.

This guide explains how it works and why it is built the way it is, so that you can decide whether its guarantees
fit what you want to run. It describes the code on `main`.

> **In short.** Each `Context` is its own wasm instance with its own linear memory, so JavaScript can't reach Python
> objects or another context's heap. Everything crosses the boundary through a flat set of exported functions and
> four imported ones; values cross as integer handles or bytes. Python functions you register become JavaScript
> globals, and they are the only way the script can affect the world outside the sandbox.

## The job

The main user is programmatic tool calling: a language model writes a short script that calls tools, combines their
results and returns a value. The script is untrusted, it calls tools that may take seconds, and it must be stopped
if it loops or allocates without end. That job sets the priorities:

| What the job needs | What quickjs-rs does |
| --- | --- |
| Run code nobody reviewed | Every context is a separate wasm instance; the engine never sees a host pointer. |
| Give the script tools | Registered Python callables become JS globals; async ones return promises. |
| Stop runaway scripts | A per-eval wall-clock deadline interrupts JS; a memory limit caps the QuickJS heap. |
| Keep a run's state | A snapshot copies the whole linear memory, closures and pending promises included. |
| Start fast, ship easily | The wasm is compiled once per process and shared; each context costs one instantiation. |

- The **Python API** is what you import. `Runtime` holds configuration (limits, clock, module loader, transform policy)
  and makes contexts. `Context` evaluates code and registers host functions.
- The **host adapter** in `_engine.py` turns Python values into calls on the guest's exports, reads results back out
  of linear memory with bounds checks, and answers the guest's imports: host calls, the interrupt poll, and module
  loading.
- The **guest** (`crates/quickjs-wasm`) is a reactor-mode wasm module that wraps one quickjs-ng runtime and one
  context. It exports about fifty small functions (`new_string`, `get_prop`, `eval_code`, `resolve_deferred`, …)
  and imports four.
- The **transform guest** (`crates/quickjs-wasm-transform`) is a separate wasm module built on
  [OXC](https://oxc.rs/). It strips TypeScript before QuickJS sees the source.

## What quickjs-rs is not

- **Not a browser or Node.** There is no `console`, `fetch`, `setTimeout`, filesystem or network. A script can do
  only what the ECMAScript built-ins and your host functions allow.
- **Not a process boundary.** The sandbox runs in your Python process. A bug in wasmtime itself could cross it; see
  [the security model](/security).
- **Not a type checker.** TypeScript types are erased, not checked.
- **Not stable yet.** The package is experimental and its API may change between minor versions.

- [Quickstart](/quickstart) gets code running in a minute.
