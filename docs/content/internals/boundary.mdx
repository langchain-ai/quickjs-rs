---
title: The wasm boundary
description: The flat ABI between Python and the guest: memory ownership, handles, status codes and reentrancy.
---

> **In short.** The host and the guest share nothing but the guest's linear memory and a list of functions that take
> and return integers. Inputs are written into guest memory through `qjs_alloc`, outputs come back through a
> one-slot result buffer, and JS values are referred to by **handles**: 32-bit guest pointers to boxed rquickjs
> `Persistent<Value>`s. Every export catches panics and reports a status code. Every read the host makes out of guest
> memory is bounds-checked, because after untrusted JS has run, nothing in that memory can be trusted.

## Why a flat ABI

The alternatives were the WebAssembly component model (typed interfaces generated by tooling), or a serialization
format with one "call" export. quickjs-rs uses neither: the guest exports about fifty plain functions such as
`new_string(ptr, len) -> handle` and `get_prop(obj, key_ptr, key_len, out) -> status`, and the host composes them.
That keeps both sides small, keeps wasmtime-py (which has no component-model support for this use) as the only
runtime dependency, and puts the marshalling policy in one place, the Python adapter, rather than duplicated on
both sides. The cost is many crossings for deep values, which is why containers get a [JSON fast
path](/guide/values#the-json-fast-path).

## Passing bytes in and out

**In.** The host calls `qjs_alloc(len)` to get a buffer in guest memory, writes bytes into it with
`Memory.write`, passes `(ptr, len)` to an export, and frees it with `qjs_free(ptr, len)` when the export returns.
Out-parameters (a handle, a bool, a number's bits) are 4- or 8-byte slots allocated the same way.

**Out.** Exports that produce bytes (`get_string`, `get_bigint`, `to_json`, `type_of`, `get_arraybuffer`,
`compute_memory_usage`, …) put them in a guest-side `RESULT` buffer. The host reads `qjs_last_ptr()` and
`qjs_last_len()`, copies the bytes out, and calls `qjs_result_free()`. The slot holds one result at a time; the host
reads it immediately.

**Checks.**

- On the host, `_Instance.read(ptr, len)` rejects any range outside the current `memory.data_len` before slicing.
  Pointers the guest hands out (`qjs_last_ptr`, import arguments) are treated as untrusted offsets.
- In the guest, `read_input` rejects a null pointer with a non-zero length; reads past the end of linear memory
  trap, which is contained by the sandbox.
- Length caps guard against host-driven exhaustion: 64 MiB for BigInt, binary and JSON inputs; 4096 bytes for a
  module name and 16 MiB for module source coming back from the loader.
- Strings cross as UTF-8 and are validated (`std::str::from_utf8` in the guest, `.decode()` on the host).

## Handles

A handle is `Box::into_raw(Box::new(Persistent::save(&ctx, value))) as i32`: a pointer into guest memory to a boxed,
lifetime-detached rquickjs value that holds one QuickJS reference. Using it restores a `Value` inside the live
context; `free_value` drops the box, which releases the reference. `0` is the null handle.

The guest doesn't validate handles beyond the null check: it dereferences whatever pointer it is given. Safety comes
from the host side, which only passes handles it minted or received, and wraps each one in a `QjsHandle` with a
`disposed` flag, so a disposed handle raises `InvalidHandleError` before it reaches the guest. The public `Handle`
adds the owning-context check. If a bad pointer ever did reach the guest, the damage would be confined to that
guest's memory.

Ownership is explicit per export. Handles returned by `new_*`, `get_*`, `eval_*`, `dup_handle` and `call_*` belong
to the caller. `resolve_deferred` and `reject_deferred` take ownership of the value handle they're given. Handles
for a host call's `this` and arguments belong to the guest and are freed when the call returns, so the host reads
them by value and never keeps them.

## Status codes

Fallible exports return an `i32` status and write their result to an out slot:

| Code | Name | Meaning |
| --- | --- | --- |
| `0` | `STATUS_OK` | Success |
| `1` | `STATUS_JS_ERROR` | A JS exception is pending; the host takes it with `last_exception` |
| `2` | `STATUS_BAD_INPUT` | Null or invalid pointer, bad UTF-8, wrong value type, input over a cap, unknown deferred id |
| `3` | `STATUS_PANIC` | A Rust panic was caught at the export boundary |
| `4` | `STATUS_NO_ENGINE` | The QuickJS runtime or context couldn't be created |

Every export body runs inside `catch_unwind`. The guest is built with `panic = "unwind"` precisely so this works:
under `panic = "abort"`, `catch_unwind` does nothing and a panic would abort the instance; letting it unwind across
the wasm boundary would be undefined behavior.

## Imports

The guest imports four functions from `env`, plus WASI:

| Import | Signature | Called when |
| --- | --- | --- |
| `host_call` | `(name_ptr, name_len, this, argc, argv_ptr) -> handle` | JS calls a registered host function. Returns a result handle, or `-1` for failure |
| `host_interrupt` | `() -> i32` | QuickJS polls its interrupt handler. Non-zero stops execution |
| `host_module_normalize` | `(base_ptr, base_len, spec_ptr, spec_len, out_len_ptr) -> ptr` | QuickJS resolves an import. Returns a `qjs_alloc`'d name, or `0` |
| `host_module_load` | `(name_ptr, name_len, out_len_ptr) -> ptr` | QuickJS loads a module. Returns `qjs_alloc`'d source, or `0` |
| `wasi_snapshot_preview1.clock_time_get` | `(clock_id, precision, out_ptr) -> errno` | Shadowed only when the runtime has a `clock` |

Host-side import bodies never raise into wasmtime: any Python exception becomes the failure value (`-1`, `0`, or a
WASI errno), and the guest turns that into a JS error. The module imports return memory the host allocated in the
guest with `qjs_alloc`; the guest copies it and frees it.

## Reentrancy

A host function that returns a value has to build it, and building values means calling exports (`new_string`,
`new_object`, …) while the guest is still inside the outer `eval`. rquickjs's `Context::with` takes a lock, and the
engine sits in a `RefCell`, so a naive nested entry would panic with "already borrowed".

The guest handles this in `with_context` (`engine.rs`). The outermost entry records the live raw `JSContext` in a
thread-local, `CURRENT_RAW_CTX`, and clears it with a drop guard on the way out, including on unwind. A nested
entry finds it set and rebuilds a `Ctx` from the raw pointer instead of re-locking. The host side mirrors this with
`_CUR` (see [architecture](/internals/architecture)), saved and restored around every export call.

## Exceptions

After `STATUS_JS_ERROR`, the host calls `last_exception` to take the pending exception as a handle and reads
`name`, `message` and `stack` off it. A thrown non-Error value (`throw 42`) has no string `name`; the host coerces it
with `String(v)`-like rules into the message and names it `Error`. `new_error` and `throw` let the host create a
specific error (used for sanitized host errors and cancellation).

The full list of exports and their signatures is in the [ABI reference](/reference/abi).
